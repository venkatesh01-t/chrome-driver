Frequently Asked Questions

Everything you need to know about self-healing test automation and the Chrome-Driver locator engine.

How does Shannon Entropy filtering eliminate dynamic ID hallucination? ▼

Modern frontend frameworks (React, Angular, Tailwind, Emotion, and CSS Modules) frequently generate volatile pseudo-random IDs like id=":r4f:-8947" or ng-reflect-input-e92b. When naive test recorders capture these, the tests fail immediately upon subsequent builds.

Chrome-Driver calculates the Shannon information entropy of element attributes. High-entropy strings or known framework regex patterns are flagged as volatile noise and discarded. The engine then uses contextual DOM graph traversal to anchor the element to stable semantic landmarks such as preceding <label> tags or table headers.

Why is Chrome-Driver AST Recorder superior to legacy Selenium IDE? ▼

Legacy Selenium IDE was designed in the Web 1.0 era: it records fragile absolute XPaths (e.g., /html/body/div[2]/table/tbody/tr[4]/td[2]/button) that crumble when a developer inserts an extra div or banner. Additionally, running side-by-side recording windows squashes the browser viewport, breaking responsive CSS media queries.

Chrome-Driver AST Recorder compiles interactions using AST transformation into production Python code, offers ranked 3-locator self-healing tuples, pierces multi-level Shadow DOMs, and operates inside the Chrome Manifest V3 Side Panel without disturbing viewport geometry.

How does the 3-tier self-healing runtime prevent test flakiness? ▼

Every recorded action produces a ranked 3-tuple of locators: Primary (data-testid, aria-label, unique CSS), Contextual (label/row XPath axis), and Structural (nth-of-type fallback).

In Selenium 4, the test executes via our custom smart_find(driver, locators) wrapper which automatically handles StaleElementReferenceException retries and falls back across the tuple. In Playwright Python, it generates strict-mode safe chaining using .or_() with visible=true filters.

Can it record actions inside Shadow DOM and nested iframes? ▼

Yes. By capturing interactions via event.composedPath(), the recorder reconstructs the exact shadow boundary hierarchy. For Playwright, it generates pierced locator chains (#shadow-host >> #inner-btn). For Selenium 4, it leverages JavaScript shadow root traversal and frame context switching commands.

How do I run the generated Python tests in headless CI/CD pipelines? ▼

When you export using the Enterprise (CI/CD) or Pytest Suite tabs, the generator automatically injects stealth flags (--headless=new, --disable-blink-features=AutomationControlled), explicit WebDriverWait conditions, and parameterizes sensitive credentials with os.getenv() so your scripts run seamlessly in GitHub Actions, GitLab CI, and Docker.
